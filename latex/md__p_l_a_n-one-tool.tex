{\bfseries{RFC:}} none — objective from ARCHITECT\textquotesingle{}s prompts and rulings (Rulings below). {\bfseries{Date:}} 2026-\/11-\/26 (third update: Stage 7C written in full, Ruling 25) {\bfseries{BLESSED Compliance:}} verified {\bfseries{Language Constraints:}} C++17 / JUCE 8.\+0.\+17 + JAM\hypertarget{md__p_l_a_n-one-tool_autotoc_md79}{}\doxysection{\texorpdfstring{Context}{Context}}\label{md__p_l_a_n-one-tool_autotoc_md79}
The first plan hand-\/rolled what JAM already does: a page renderer, themes, a wrapper, a pager, a YAML reader. ARCHITECT stopped it. This plan deletes that code and builds the seam between blocks that exist.

Steps 0 to 43 are done. Their code is on disk and is not compiled. Step 45 (the one build) is their proof. Step 44 of the second update is void: Ruling 25 deleted {\ttfamily Json\+Program}, which it changed.

Stage 7C is the rest of the JSON work. ARCHITECT ruled (Ruling 25) that every JSON type other than {\ttfamily Json\+Document} and its established pattern is garbage, and the deletion is done (Step 44b). What remains is the cause that made those types: in the JSON family a scalar is a token inside its container, not an element ("{}\+The child element exists only for a container token"{}, {\ttfamily jam\+\_\+\+Json\+Document.\+h:244-\/252}; {\ttfamily get\+Child\+By\+Token} returns nullptr for it, {\ttfamily jam\+\_\+\+Json\+Document.\+cpp:132-\/137}). A value has no node, so each consumer built a carrier to point at one. MANIFESTO E, the verdict: "{}\+If the data does not fit the implementation, the parse is wrong or the implementation is wrong."{} Stage 7D gives the correction: {\ttfamily Json\+Document} follows the Document pattern (Ruling 27).\hypertarget{md__p_l_a_n-one-tool_autotoc_md80}{}\doxysection{\texorpdfstring{Overview}{Overview}}\label{md__p_l_a_n-one-tool_autotoc_md80}

\begin{DoxyItemize}
\item {\ttfamily jam::\+\+Document} holds the one line model. Every document calls it.
\item A page is a {\ttfamily juce::\+\+Component} painted by a Look\+And\+Feel through {\ttfamily juce::\+\+Graphics}. {\ttfamily Terminal\+Graphics\+Context} turns it into bytes.
\item ling builds and carries the rendering library. saw is {\ttfamily cat}. With ling\textquotesingle{}s libraries it renders as {\ttfamily bat}.
\item {\ttfamily Json\+Document} is the complete AST of JSON: every value is an element. A jq program is a {\ttfamily Json\+Document} family with a linked tree ({\ttfamily Id::\+to}, {\ttfamily Id::\+in}). A run creates its result values as elements of a value-\/stream {\ttfamily Json\+Document}. {\ttfamily Json\+Validator} holds every rule. {\ttfamily Json\+Writer} renders elements. No other JSON type exists.

\item A new identifier, text, colour, metric, lexeme, operator, builtin name or builtin definition is a row in {\ttfamily jam/\+cast/\+\texorpdfstring{$\ast$}{*}.md}, {\ttfamily ling/\+cast/\+\texorpdfstring{$\ast$}{*}.md} or {\ttfamily saw/\+cast/\+\texorpdfstring{$\ast$}{*}.md}. {\ttfamily generated/} is written by cast in the build. \item Slim rule: saw links {\ttfamily jam\+\_\+syntax\+\_\+tree} (deps {\ttfamily juce\+\_\+core}, {\ttfamily jam\+\_\+core}, {\ttfamily user-\/modules-\/info.\+md:152}) and no GUI module. MCP and every verb except {\ttfamily page} load no library.

\item Windows: the same mechanism, {\ttfamily language.\+dll} beside {\ttfamily liblanguage.\+dylib} ({\ttfamily files.\+md:30-\/31}).
\item Clean room: never open {\ttfamily jq/\+src}, {\ttfamily bat/\+src}, or a grammar file. Running the installed {\ttfamily jq} or {\ttfamily bat} as a witness, and reading their tests and docs, is permitted. A witness run shows user-\/visible output only. It never decides an internal design (Ruling 26).
\item String rule (Ruling 18). Text is a {\ttfamily std::\+string\+\_\+view} over its source. {\ttfamily juce::\+\+String} appears only as the argument or the result of a JUCE call, or as the value of an existing {\ttfamily juce::\+\+String} property; a result is read at once with {\ttfamily jam::\+\+Strings::\+get\+View} ({\ttfamily jam\+\_\+\+Strings.\+h:646}).
