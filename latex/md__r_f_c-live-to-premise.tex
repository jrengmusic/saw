The premise has three claims. Each claim fails today in part.

Fastest  &Fails on one small file, on a regex tree search with no required literal, and on tree replace against python. Holds on literal tree search against {\ttfamily rg} and {\ttfamily grep}, and against {\ttfamily sed} run for each matching file.  &Section S1 to S5  \\

What holds (observed):


\begin{DoxyItemize}
\item The functional suite passes 91/\+91 ({\ttfamily nvim -\/-\/headless -\/l test/\+run.\+lua \texorpdfstring{$\sim$}{\string~}/.local/\+bin/\+saw}, exit 0).
\item For 10 of 11 patterns on a 3,079-\/file corpus, {\ttfamily saw find} gives the same lines as {\ttfamily rg}, after CR removal, path prefix removal and a sort. The other pattern is {\ttfamily (?i)juce\+\_\+api} (R7).
\item A wrong or missing {\ttfamily -\/-\/expect} writes zero bytes. A failed second file leaves the first file at its original bytes.
\item {\ttfamily undo} refuses a file that changed after the apply.

{\bfseries{Facts that bound the target.}}


\begin{DoxyItemize}
\item A {\ttfamily juce\+\_\+core} program cannot start in less than about 2.\+46 ms in this loop. {\ttfamily rg} takes 2.\+75 ms for a whole search. {\ttfamily sed} takes 1.\+45 ms and {\ttfamily grep} takes 1.\+47 ms.
\item An empty C program takes 1.\+58 ms. That is more than {\ttfamily grep} takes for a whole search. A third-\/party binary cannot beat Apple\textquotesingle{}s {\ttfamily grep} and {\ttfamily sed} on one call to one small file in this loop.
\item Thus "{}fastest"{} on one small file is out of reach. "{}\+Fastest for one batch in one process"{} is in reach.
